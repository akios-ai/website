Getting started Threat model GitHub

What AKIOS is

You keep your agent as it is: its code, its model, its libraries, its keys. AKIOS puts a fence around it.

The cage

A fence that the operating system holds, not the agent.

A policy file declares what the agent may touch: files, programs, network, environment variables, resources. The operating system enforces it, without root. If this host cannot enforce a clause, the run does not start, unless you accept a degraded run, and then the ledger says so before the agent starts.

Tests: K-FS-01 to K-FS-05, K-FS-07, K-SYS-01, K-NET-01 on Linux; M-FS-01 to M-FS-07, M-SYS-01, M-NET-01 on macOS. Fail-closed rules: threat model §6.

The doors

The way into the cage. Today, one door.

Door 1, akios run -- <command>, wraps any program: a coding agent, a Python script, a LangChain application. The policy applies to the program and to every process it starts (K-FS-01, M-FS-01).

Doors 2 and 3 are on the roadmap: an in-process Python Sandbox(...) API, and an MCP server through which agents route their tool calls.

The proof

A sealed record that anyone can check.

Every run leaves a hash-chained ledger with signed checkpoints. akios verify checks an exported run on any machine; with --key, it also checks that the run was signed by the key you expect.

Tests: V-TAMPER-01 to V-TAMPER-07, V-CP-01 to V-CP-03, V-KEY-01, V-XOS-01.

AKIOS is not an agent framework, a workflow engine, a model client, a cloud service, or an organisation-level governance tool. Why this design: why containment.

From the policy to the proof

  1. Policy

    akios init writes akios.policy.yaml: what the program may read, write and execute, network or none, the environment variables it receives, resource limits. akios policy explain says, for this host, how each clause is enforced and whether the run would start.

  2. Run

    akios run -- <command> records its decision before the command starts (threat model §6); the operating system then enforces the policy on the command and every process it starts.

  3. Record

    The ledger of the run: events chained by SHA-256, checkpoints signed with Ed25519, the enforcement of each clause and the outcome; editing, inserting, deleting, reordering or truncating events makes akios verify fail (V-TAMPER-01 to V-TAMPER-07). On macOS, also what the cage refused (M-SYS-02); on Linux, capturing refusals is planned.

  4. Check

    akios report describes the run from its verified ledger. akios verify checks the exported bundle on Linux, macOS or Windows (V-XOS-01), and with --key against the key you expect (V-KEY-01).

Two platforms, and their limits

Each property holds for the wrapped program and all its descendants. The test identifiers are those of the threat model; its test index gives the file of each test, where it runs, and where and when it passed.

Linux

Landlock, seccomp, namespaces, read-only bind mounts and rlimits, without root.

  • filesystem and exec: Landlock, ABI 3 (Linux 6.2) or later (K-FS-01 to K-FS-04). The signing key and the ledger store are unreachable (K-FS-05).
  • filesystem.protect: read-only bind mounts in the run's own mount namespace (K-FS-07).
  • Baseline: kernel modules, mount, ptrace, bpf, io_uring, unshare and other calls return EPERM, by seccomp after PR_SET_NO_NEW_PRIVS (K-SYS-01). The program cannot read or write the wrapper's memory (K-PROC-01).
  • network: none: a new network namespace with only the loopback up (K-NET-01); without unprivileged namespaces, IPv4 and IPv6 sockets are denied and the ledger records the fallback (K-NET-02).
  • resources: rlimits and a watchdog (R-RES-01, R-RES-02). environment: only the variables the policy passes (R-ENV-01).

Limits

  • Per-run memory and process accounting with cgroups v2: planned (K-RES-03).
  • Below Linux 6.12, a same-user child can kill the wrapper; the run then fails verification (K-PROC-02 checks both sides).
  • Refusals are not captured: Landlock and seccomp do not log them by default. A capture is planned.
  • Without a delegated cgroup, a descendant that calls setsid() survives the wall-clock kill.
  • Network is none or all; a domain allowlist is experimental and not enforced in 2.0.

Requirements: Landlock enabled (ABI 3, Linux 6.2 or later) for filesystem and exec, unprivileged user namespaces for network: none and filesystem.protect; Python 3.10 to 3.14; no root.

macOS

The system sandbox, a denial reader and the developer-tool shims, without root and without an entitlement.

  • One Seatbelt profile per run, the sandbox built into macOS, enforces baseline, filesystem, exec and network; every process the program starts inherits it and cannot lift it (M-FS-01 to M-FS-04).
  • The signing key and the ledger store are unreachable (M-FS-05); the policy file of the run is read-only inside the cage (M-FS-06); filesystem.protect keeps chosen paths read-only (M-FS-07).
  • Setuid programs do not start and a second sandbox cannot be applied (M-SYS-01); the program cannot signal the wrapper or obtain its task port (M-PROC-01).
  • network: none: TCP, UDP and name resolution fail, loopback included (M-NET-01). network: all: Unix-domain sockets outside the write paths still fail (M-NET-02), and TLS verifies certificates with the system's certificates (M-NET-03).
  • Denial reader: what the cage refused is read from the sandbox reports of the system log, recorded in the ledger, and named by akios run and akios report, also after exit code 0 (M-SYS-02).
  • Developer-tool shims: before the run, akios run asks xcrun --find for the tool behind each shim of /usr/bin the command uses, such as python3 or git; in the cage the shim finds it in the lookup cache, which it can read but not list (M-SYS-01; policy v0 §5.7).
  • resources: CPU time and file size are capped, also for a program that ignores SIGXCPU; at the wall-clock limit the run is stopped, and a descendant that left the process group is killed (M-RES-01, M-PROC-02, R-RES-02).

Limits

  • memory_mb is not enforced: a policy that sets it is refused unless the run is degraded.
  • Other processes of the same user can read each other's initial environment; AKIOS overwrites the unpassed values in its own (M-PROC-01).
  • No private loopback: with network: none, a program that runs its own local server needs network: all.
  • The record of denials comes from the system log: a count is a lower bound, and a standard account was not tested.
  • ps, top and pgrep do not work in the cage, a program cannot apply its own sandbox there (M-SYS-01), and a sign-in kept in the Keychain is not available.
  • Tested on macOS 26.6.2 on Apple Silicon; Intel Macs and other macOS versions were not tested.

Requirements: macOS on Apple Silicon (tested: macOS 26.6.2, with Python 3.12); Python 3.10 to 3.14; no root and no entitlement. akios doctor runs a self-test of the sandbox.

Elsewhere, Windows included, akios run refuses unless the run is degraded; akios verify and akios report have no platform check. Every known limit of 2.0, on Linux and on macOS, is listed in one place: threat model §8. Out of scope, among others: kernel exploits, root, other processes of your own user outside the cage, the content of encrypted traffic (threat model §3).

Security and contact

Do not report a vulnerability in a public issue. Use GitHub's private vulnerability reporting on the akios repository. If the form is unavailable, write to hello@akios.ai. Reports are handled on a best-effort basis; see the security policy.

Bugs, questions, feature requests: GitHub Issues. Anything else: hello@akios.ai. Help is given on a best-effort basis; see getting help.
